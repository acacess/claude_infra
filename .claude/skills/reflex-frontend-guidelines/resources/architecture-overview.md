# Architecture Overview - Reflex Applications

Complete guide to Reflex architecture and how state synchronization works.

## Reflex Architecture

### How Reflex Works

```
┌─────────────────────────────────────┐
│         Browser (Frontend)           │
│  - Renders UI from Python components│
│  - Sends events via WebSocket       │
└──────────────┬──────────────────────┘
               │ WebSocket
               │ (Events & State Updates)
               ▼
┌─────────────────────────────────────┐
│    Reflex App (Frontend Server)      │
│  - State classes (rx.State)          │
│  - Event handlers (async methods)    │
│  - UI component generation           │
│  - Generates React components        │
└──────────────┬──────────────────────┘
               │ HTTP/REST API
               │ (Data fetching)
               ▼
┌─────────────────────────────────────┐
│    FastAPI Backend (API Server)      │
│  - REST API endpoints                │
│  - Business logic                    │
│  - Database access (SQLAlchemy)      │
│  - Authentication (JWT)              │
└─────────────────────────────────────┘
```

**Key Concept:**
- **Reflex app** manages state and UI (frontend server)
- **FastAPI backend** provides REST APIs for data (backend server)
- **Browser** displays React UI generated by Reflex
- **WebSocket** syncs state between browser and Reflex
- **HTTP** for Reflex → FastAPI API calls

## Component Lifecycle

### 1. Initial Page Load

```python
@rx.page(route="/", on_load=AppState.load_data)
def index() -> rx.Component:
    return rx.container(
        rx.heading("Welcome"),
        rx.text(AppState.message)
    )
```

**What happens:**
1. User navigates to `/`
2. Reflex generates React components from Python
3. `on_load` handler executes (loads data)
4. Initial state sent to browser
5. Page renders with data

### 2. User Interaction

```python
class CounterState(rx.State):
    count: int = 0

    def increment(self):
        self.count += 1

def counter() -> rx.Component:
    return rx.button(
        f"Count: {CounterState.count}",
        on_click=CounterState.increment
    )
```

**What happens:**
1. User clicks button
2. Event sent to backend via WebSocket
3. `increment()` method executes
4. State updates (`count += 1`)
5. New state sent to frontend
6. UI re-renders automatically

## State Synchronization

### Per-User State

Each user gets their own state instance:

```python
class UserSession(rx.State):
    username: str = ""
    cart_items: list[dict] = []

    def add_to_cart(self, item: dict):
        """Each user has their own cart."""
        self.cart_items.append(item)
```

**Important:** State is **per-session**, not global. User A's state doesn't affect User B's state.

### State Hierarchy

```python
# Base state
class State(rx.State):
    pass

# Authentication substate
class AuthState(State):
    user: dict | None = None

# Shopping substate
class ShoppingState(State):
    cart: list[dict] = []

    async def checkout(self):
        # Can access AuthState
        auth = await self.get_state(AuthState)
        if not auth.user:
            return
        # Process checkout...
```

## Component Rendering

### Server-Side Python → Client-Side React

Your Python code:
```python
def user_card(name: str, email: str) -> rx.Component:
    return rx.card(
        rx.heading(name),
        rx.text(email)
    )
```

Gets compiled to React:
```jsx
<Card>
    <Heading>{name}</Heading>
    <Text>{email}</Text>
</Card>
```

**You write Python, users get React.** Best of both worlds!

## Event Handling

### Synchronous Events

```python
class FormState(rx.State):
    name: str = ""

    def set_name(self, value: str):
        """Sync event - updates immediately."""
        self.name = value
```

### Asynchronous Events

```python
class DataState(rx.State):
    data: list[dict] = []
    loading: bool = False

    async def fetch_data(self):
        """Async event - can do I/O."""
        self.loading = True
        async with httpx.AsyncClient() as client:
            response = await client.get("/api/data")
            self.data = response.json()
        self.loading = False
```

## Data Flow

### Typical Request Flow

```
1. User clicks "Load Posts" button
   ↓
2. Event sent to backend: post_state.load_posts()
   ↓
3. Backend sets loading = True
   ↓
4. State update sent to frontend (loading spinner shows)
   ↓
5. Backend fetches from API (async)
   ↓
6. Backend sets posts = [...data...], loading = False
   ↓
7. State update sent to frontend (posts display)
```

## Performance Considerations

### State Updates are Atomic

```python
# ❌ BAD: Multiple updates = multiple re-renders
def update_user(self):
    self.name = "John"     # Re-render
    self.email = "..."     # Re-render
    self.age = 30          # Re-render

# ✅ GOOD: Single update = one re-render
def update_user(self):
    self.name = "John"
    self.email = "..."
    self.age = 30
    # Re-render happens once after method completes
```

### Computed Vars are Cached

```python
class DataState(rx.State):
    items: list[dict] = []

    @rx.var
    def filtered_items(self) -> list[dict]:
        """Cached - only recomputes when items changes."""
        return [item for item in self.items if item["active"]]
```

## Key Takeaways

1. **State lives on backend** - Python server, not browser
2. **WebSocket sync** - Bidirectional communication
3. **Per-user sessions** - Each user has their own state
4. **Python → React** - Write Python, get React components
5. **Async events** - Can do I/O operations
6. **Computed vars** - Cached derived values
7. **Substates** - Modular state organization
